# F: Privacy and Data Control

## Goal

Give the user explicit control over financial-data access, transmission, retention and recovery.

## Scope

- In: local access boundary, provider-consent policy, minimal disclosure, safe logs/artifacts, local file protections, retention choices, export/deletion and backup/restore.
- Out: a claim of zero knowledge, a custom secret-management platform, financial actions, and hosted tenant/billing mechanics (G).
- Boundary: other features enforce these controls at their own seams; F owns the policy and cross-flow acceptance evidence.

## Acceptance Criteria

```gherkin
Feature: Privacy and Data Control

  @core
  Scenario: R1 — Denied processing consent prevents egress
    Given a user denied remote extraction or notification disclosure
    When a workflow requests that processing
    Then no financial content leaves through that operation and the denial remains actionable

  @core
  Scenario: R2 — Unauthorized local requests cannot access financial data
    Given the financial local service is running
    When an untrusted webpage or unauthorized requester submits a financial read or mutation
    Then the request is rejected without exposing or modifying account data

  @core
  Scenario: R3 — Sensitive content does not enter operational logs
    Given fixtures contain secret canaries and private statement fields
    When successful and failing workflows produce operational logs
    Then logs expose only approved metadata and contain none of the protected canaries or raw payloads

  @core
  Scenario: R4 — Export deletion and restore follow selected policy
    Given a user has admitted data and an application backup
    When the user exports deletes application-owned records and tests restoration from the retained backup
    Then the export is exact deletion scope is reported and restoration reproduces the backed-up ledger without silent loss
```
