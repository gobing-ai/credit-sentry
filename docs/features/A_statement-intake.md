# A: Statement Intake

## Goal

Turn explicitly selected statement files into complete, reviewable transaction candidates with source evidence.

## Scope

- In: supported manual CSV/text-PDF intake, file/source identity, bounded deterministic or consented model extraction, validation and explicit unsupported-format handling.
- Out: ledger admission (B), scheduled mailbox connection (E), public parser plugins and universal bank/OCR support.
- Boundary: A returns candidates and issues; B owns accepted records; D presents review; F governs data handling.

## Acceptance Criteria

```gherkin
Feature: Statement Intake

  @core
  Scenario: R1 — Supported source produces traceable candidates
    Given a labeled supported statement and a selected account
    When the user imports the file
    Then all expected candidate rows retain exact source locators and validation issues before any ledger admission

  @core
  Scenario: R2 — Unusable input cannot silently succeed
    Given an unreadable or unsupported statement
    When the user attempts import
    Then the import reports an actionable failure or review state and admits no transactions

  @core
  Scenario: R3 — Remote extraction requires consent
    Given remote processing is disabled
    When extraction would require a remote model
    Then no content is transmitted and the user receives an explicit processing-choice requirement

  @core
  Scenario: R4 — Interrupted extraction can be retried
    Given an import attempt stops before review
    When the user retries the same source
    Then the existing source identity is reused and the attempt history records recovery without duplicate admission
```
