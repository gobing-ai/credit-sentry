# G: Hosted Service

## Goal

Provide a supportable hosted CreditSentry service with isolated customer data and verifiable entitlements.

## Scope

- Deferred in full: hosted identity, tenant authorization, billing/entitlements, quotas, operational recovery and a selected deployment adapter after demand and economics are validated.
- Out: a parallel financial pipeline, mandatory Cloudflare migration, a preset commercial license/price, and a claim that storage encryption establishes zero knowledge.
- Boundary: reuse A–F domain behavior; G owns the hosted identity/operations trust boundary.

## Acceptance Criteria

```gherkin
Feature: Hosted Service

  @core
  Scenario: R1 — Hosted operations enforce tenant ownership
    Given two authenticated tenants have separate financial records
    When one tenant requests another tenant's identifiers across read write export and background-job paths
    Then every cross-tenant operation is rejected without data leakage

  @core
  Scenario: R2 — Billing event replay does not duplicate entitlements
    Given a signed provider event was already processed
    When the event is replayed or events arrive out of order
    Then entitlements reconcile with authoritative billing state without duplicate effects

  @core
  Scenario: R3 — Quota exhaustion preserves accepted records
    Given a tenant reaches configured processing or cost limits
    When a new extraction job is submitted
    Then the service reports a bounded refusal while preserving previously accepted records and job state

  @core
  Scenario: R4 — Hosted deletion and recovery have observable scope
    Given a tenant requests deletion and an operator performs an authorized recovery drill
    When the documented lifecycle executes
    Then active data credentials and queued work follow the deletion policy and recovery evidence identifies backup retention limits
```
