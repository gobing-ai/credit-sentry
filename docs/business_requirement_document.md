## 1. 业务机会与定位

多卡用户可能缺少持续核对交易、订阅价格变化和陌生小额扣款的时间。CreditSentry 的价值
假设是：以可追溯的账单证据减少人工审阅成本，帮助用户发现值得核实的异常候选。

“异常候选”不代表已证实欺诈、银行错误或可追回款项。信用卡账单通常提供交易级记录；
没有收据时，不能承诺商品级明细审计或推断每笔费用的具体成因。

首批目标用户是愿意导出账单并运行本地工具的个人多卡用户。托管版面向不愿维护本地环境
的用户是后续假设，不是当前必须建设的第二套产品。正式产品边界见 PRD，不能把通用
AI Coding Agent 平台的沙箱、技能、WBS、Git 自动化功能直接转为 CreditSentry 的需求。

## 2. 商业假设与验证

| 假设 | 验证办法 | 当前结论 |
|---|---|---|
| 用户为订阅涨价/重复扣款核对耗费明显时间 | 访谈真实多卡用户，记录最近一次核对过程和漏查案例 | 未验证 |
| 本地数据控制权具有购买/使用价值 | 测试本地工具的安装、导入、理解告警流程与远程处理接受度 | 未验证 |
| AI 提取能降低导入成本 | 用已标注且获授权的代表性样本比较提取、纠错时间和漏行情况 | 未验证 |
| 订阅价格 $7.99–$9.99/月可行 | 测试支付意愿，同时计入模型、消息、存储、支持及接入审核成本 | 仅为定价实验区间 |
| 自动监控能带来留存 | 先验证手动报告有用，再测试单一连接器和通知渠道的重复使用 | 未验证 |
| 社区可贡献长尾格式 | 观察真实贡献和维护成本，不以插件平台作为前置条件 | 未验证 |

不承诺“全球银行支持”“精准欺诈检测”“零误报”“毫秒级告警”或 1–2 周完成产品。
使用固定支持集和可重复结果描述能力；具体交付门槛由路线图及设计文档管理。

## 3. 竞争研究应回答的问题

原稿对 Rocket Money、Empower、Firefly III、Maybe、Copilot Money 和 Monarch 的价格、
地域、隐私、数据导入及准确率描述未提供可核验依据，已删除确定性结论。这些产品名称可
作为后续研究候选，不能作为已证实的竞争差异。

下一轮研究逐个核对官方来源、日期和套餐：支持的导入方式、数据处理/删除安排、订阅追踪、
用户自托管能力、价格及目标市场。差异化必须通过真实工作流验证，而不是“对方有隐私风险”
之类未经支持的判断。

## 4. 隐私承诺与 AI 角色

本地存储不等于全程本地处理。若用户选择远程模型提取，相关内容会离开设备；提供方、
发送字段及处理/保留条件必须在传输前说明并获得明确选择。普通加密不能被包装成零知识。

AI 用于提出可审阅的数据候选及辅助解释；不能自行确认欺诈、改变财务记录、取消订阅、
发起争议或付款。“Parser/Auditor/Copilot Agent”不是必须分别部署的自主 Agent；
当前范围采用有边界的提取与确定性判定。隐私机制和信任边界见
[03_ARCHITECTURE](03_ARCHITECTURE.md)。

## 5. 商业化、实体与许可的待决事项

| 事项 | 修订后的处理 |
|---|---|
| 中美双实体 | 仅保留为运营设想。不得据此推导跨境数据访问或合规已经成立；研发默认使用合成/授权脱敏样本，真实数据访问另行设计和授权。 |
| 收款与 MoR | 普通 Stripe Checkout/Billing 与 Merchant of Record 不是同一选择。Stripe 将 Managed Payments 单独列为 MoR 方案；实际适用性需核对。[官方说明](https://docs.stripe.com/payments/managed-payments) |
| Open Core / MIT / BSL | 尚未决定。仓库当前 LICENSE 为 Apache-2.0，仍带模板版权人名称；发布前由所有者确认来源、权利及分发方案。本次不改许可证。 |
| 托管服务价格 | 上述区间仅为实验假设，不是已批准报价。先验证单位经济和服务成本。 |
| 地域、隐私条款、税务 | 商业发布前明确实体、数据流、服务商、保留/删除和支持责任，不在技术草案中宣称已经合规。 |
