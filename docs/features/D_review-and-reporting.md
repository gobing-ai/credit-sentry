# D: Review and Reporting

## Goal

Let the user resolve extraction uncertainty, inspect findings and retain decisions through repeatable local reports.

## Scope

- In: CLI candidate review/correction requests, admission confirmation, finding evidence/disposition, coverage warnings and JSON/text reports.
- Out: record consistency (B), rule evaluation (C), notification transport (E), hosted tenancy (G).
- Deferred: web review surfaces and bounded read-only conversational queries require demonstrated user need; no financial-action copilot.

## Acceptance Criteria

```gherkin
Feature: Review and Reporting

  @core
  Scenario: R1 — User resolves candidate uncertainty before admission
    Given an import has unresolved candidate issues
    When the user inspects and corrects the affected fields
    Then the CLI displays source evidence and requires validation plus explicit admission confirmation

  @core
  Scenario: R2 — Report exposes evidence and coverage
    Given a completed audit with findings and incomplete history
    When the user exports JSON and views the local report
    Then both outputs include exact amounts evidence references rule versions and coverage warnings

  @core
  Scenario: R3 — User disposition survives unchanged reruns
    Given a user dismissed an unchanged finding
    When the audit and report run again
    Then the finding retains its disposition and is not presented as a new unreviewed event

  @core
  Scenario: R4 — Correction makes stale findings explicit
    Given an accepted transaction contributed to a finding
    When the user corrects the transaction and reruns the audit
    Then the report distinguishes superseded evidence from current findings and preserves the decision history
```
